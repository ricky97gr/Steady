# Steady 项目知识

> Steady 是一个个人量化研究平台：每日自动同步行情 → 计算因子 → 生成信号 → 模拟交易 → 对账 → 飞书通知。本文是项目问答能力的知识来源。

## 整体架构

单仓库、docker-compose 单机部署（不上 k8s），由 5 个容器 + 4 个代码模块组成：

| 组件 | 技术栈 | 职责 |
|---|---|---|
| **collector** | Python（SQLAlchemy + requests） | 数据采集：股票列表/日历/指数/日线/估值/财务/热点。**Tushare 主源 + akshare 兜底**（主源失败自动降级），盘中实时快照走 akshare |
| **quant-engine** | Python（SQLAlchemy + apscheduler） | 量化计算：因子计算、多因子策略信号、早盘简报组装、数据健康检查、回测引擎、通知调度与日报推送、任务台账 |
| **backend** | Go（gin + gorm + postgres） | API 服务（/api/v1）、模拟交易（下单/持仓/净值/对账）、飞书通知卡片、任务台账、早盘简报只读、**大模型 LLM 集成** |
| **frontend** | React + Ant Design（Vite） | 单页应用：数据总览/早盘简报/股票池/策略/模拟交易/回测/设置/AI 助手 |

部署：`postgres` → `collector` → `quant-engine` → `backend` → `frontend` → `nginx`（唯一对外入口 80 端口）。后端 API 无鉴权，仅监听 127.0.0.1 靠防火墙兜底。

## 关键表

| 表 | 说明 |
|---|---|
| `stock_basic` | 股票池（代码/名称/市场/行业/上市日期/状态/所属指数池） |
| `daily_price` | 日线行情（OHLC/成交量/涨跌幅/复权因子），数据主路径 |
| `daily_valuation` | 每日估值（PE/PB/市值/股息率） |
| `financial_indicator` | 财务报表指标（ROE/净利/营收等，按公告日对齐防未来函数） |
| `factor_definition` / `factor_value` | 因子定义（权重配置化）与每日因子值 |
| `strategy_signal` | 策略信号（T 日生成，含买卖动作与评分） |
| `account` / `position` / `"order"` / `trade` | 模拟交易：主账户/持仓/委托/成交 |
| `account_nav` | 账户净值快照（幂等，已存在则跳过） |
| `backtest_job` / `backtest_result` | 回测任务与结果指标（总收益/年化/最大回撤/夏普） |
| `morning_brief` | 早盘简报（sections JSONB，供页面与大模型消费） |
| `task_run` | 任务执行台账（task_name+run_date 幂等，detail 结构化） |
| `app_config` | 应用配置键值（feishu.* / tushare.token / llm.*，页面可改） |
| `notify_config` | 通知事件调度规则（weekday/trading_day/event） |
| `market_hotspot` | 热点采集（隔夜外盘/板块涨幅与资金流/活跃个股） |
| `trade_calendar` | 交易日历 |

## 数据流

```text
collector 采集 → daily_price / daily_valuation / financial_indicator / market_hotspot
   → quant-engine 19:00 算因子 (factor_value)
   → 19:30 多因子策略生成信号 (strategy_signal)
   → backend 19:35 自动交易 ExecuteDay（模拟盘：下单→持仓→净值快照）
   → 21:05 净值快照 / 21:15 每日对账（现金+持仓市值=总资产等 7 项校验）
   → 飞书卡片通知（交易结果 / 对账结果 / 早报 AI 解读）
```

回测链路独立：quant-engine 读因子与行情跑 `backtest/`（broker 模拟交易成本 + portfolio + engine），结果落 `backtest_result`，每 5 分钟消费队列。

## 定时任务时间表

**quant-engine（Python / apscheduler）：**
- 09:10 早盘简报组装（热点 + 昨日回顾 + 今日计划）落库 morning_brief
- 18:30 数据健康检查（7 项体检写 task_run 台账，18:35 推送）
- 19:00 计算因子
- 19:30 多因子策略生成信号
- 21:00 每日汇总日报推送（notify_scheduler）
- 每 5 分钟消费回测任务 / 每 1 分钟通知调度 tick

**backend（Go / 自研 Scheduler，支持重启当日补跑）：**
- 09:20 早盘简报 AI 解读（llm.enabled 门控 + 仅当日简报，飞书卡片 + 台账）
- 19:35 自动交易 ExecuteDay（幂等：当日已执行则跳过）
- 21:05 净值快照（幂等）
- 21:15 每日对账校验（7 项，偏差推送飞书告警）

## 模拟交易规则（与回测一致）

- T+1 冻结/解冻、100 股整手、加权平均成本
- 手续费：印花税万 5（仅卖出）+ 佣金万 2.5（最低 5 元）+ 滑点 0.1%
- 分板块涨跌停：主板 10% / ST 5% / 创业板 20% / 科创板 20% / 北交所 30%
- 停牌/数据缺失跳过；资金不足逐档减 100 股重试
- 一致性对照测试：`backend/internal/service/trading_consistency_test.go` 与 `quant-engine/tests/test_broker_consistency.py`

## 大模型集成（LLM）

- **硬约束：大模型绝不直接操作数据库**。LLM 是纯生成器，唯一数据入口是白名单 Go 只读方法（`BriefReader` 接口，`MorningBriefService` 实现）；数据打成 bounded prompt（简报 ≤8KB 截断），输出只当文本（页面 / 飞书卡片 / 台账），永不执行。
- 部署：云端 API，OpenAI 兼容协议，base_url 按 provider 可配（openai/deepseek/qwen/glm）。
- 配置存 `app_config.llm.*`（页面设置页可改，api_key 为 secret 只回显掩码）。
- 知识库：`docs/llm/术语表.md` + `docs/llm/项目知识.md`，compose 只读挂载进 backend 容器 `/app/docs/llm`，缺文件优雅降级（接口返回「知识库未加载」）。
- 能力：① 术语解释 ② 项目问答 ③ 早盘简报解读（手动按钮 + 09:20 定时飞书卡片）。

## 发布与部署

- 生产只发 **master**：本地 `scripts/build-release.sh` 产出 `deploy/release/steady-<日期>-<SHA>/` 三件套（install.sh + config.tar.gz + steady-images.tar.gz），VM 只运行不编译。
- 升级 = 新目录重跑 `./install.sh`；回滚 = 旧目录重跑；数据在命名卷不动。版本 = 目录名日期-SHA。
- 分支纪律：日常开发在 `dev`，功能分支 `feat/*` 基于 dev，经 PR + CI + 用户测试后合回 dev，master 只从 dev 来。

## 开发自检

- 后端：`cd backend && go build ./... && go test ./... && go vet ./...`
- 前端：`cd frontend && npx tsc --noEmit`
- 集成测试门控环境变量 `TEST_DB_DSN`（拒绝连生产库 quant_system）。
